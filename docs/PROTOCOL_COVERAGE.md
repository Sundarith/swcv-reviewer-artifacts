# Protocol coverage for the two RCM tables

This index covers eleven models and nine methods on each benchmark (198 selected conditions). It records original ledger hashes, exported-answer hashes, checkpoint-profile lineage and model asset manifests, saved chat templates, retained exact generation payloads and all observed decoding-setting variants. `saved_requests.jsonl.gz` preserves the exact retained prompts/messages and tool definitions; a request example alone is not the full protocol. Omitted request fields are marked OMITTED, not represented as explicit values. Server chat-template kwargs/context and checkpoint manifests are separately indexed. Remaining output/parser/context failures stay in the denominator.

## Selection and recorded generation settings

CTI-Bench retains aggregation k=20 retrospectively. CTIConnect uses aggregation k=10, selected from {5,10,20} on the same 290 evaluation questions, and is exploratory. The k=20 CTIConnect sensitivity result remains separate. A separate reference-CVE development sample selected the softmax baseline’s temperature; this does not select or validate the aggregation neighborhood. See configs/evaluation_selection.json.

All 198 selected conditions have saved checkpoint-profile lineage, chat-template references and retained payloads. The recorded payload settings use temperature 0 and max_tokens 512; other supplied/omitted settings are indexed per condition. The main paper summarizes the shared settings and refers here for available date evidence, without claiming complete historical timestamps. The current CTI-Bench Naive RAG config references 120,238 CVEs; its older 120,242-reference version is preserved in configs/historical.

## Historical dates

The package has server-supplied response creation windows for 40 conditions and recorded completion receipts for 187. The CSV distinguishes a condition receipt from an ancestor queue receipt. A queue completion is not an individual request timestamp, and a response window does not necessarily identify every reused answer's original generation phase. Exact original/replay/continuation boundaries are not fully recoverable from these retained structured receipts. Missing dates remain unavailable; no date was inferred from current filesystem modification time or invented from an experiment directory name. `historical_dates.json` preserves the evidence rather than asserting a full historical timeline.

## Variants and scoring

CTI-Bench uses the original identifier extraction and canonical reference label. CTIConnect retains official accepted alternatives with the declared uniform Unicode-hyphen normalization. The packaged pinned scorer and offline verifier reproduce every selected table cell. The scorer extracts case-insensitive `CWE-\d+` matches from saved prediction text, uppercases and deduplicates them, and retains the digit strings. No matching ID yields an empty set. CTI-Bench uses its canonical reference CWE and mean per-question identifier-set F1. For CTIConnect, a nonempty prediction set entirely within a supplied expanded valid-target set receives full credit under the official rule; otherwise the scorer compares with the canonical gold. Before CTIConnect scoring, only a Unicode dash between the CWE prefix and a following digit is replaced by ASCII hyphen (U+2010–U+2015, U+2212, U+FE63, U+FF0D). No hierarchy credit or additional label remapping is introduced. CRAG fallback, Fusion parser and full-evidence context continuations are distinct recorded variants. Corrected Phi CTIConnect A-RAG uses the nested-array parser recovery and scores 35.92%; its original 5.00% is historical. The CTI-Bench Phi-4 A-RAG score of 57.22% is the original recorded result from a run with a confirmed nested-array tool-parser defect. The paper retains that recorded CTI-Bench result; the corrected CTIConnect run is a separate experiment. IRCoT and bounded-evidence A-RAG are excluded.

The original ten-reader Naive RAG manifest is retained for that historical scope; it is not silently extended to the other 178 conditions. Current condition_index.json and per-condition exports cover the expanded comparison. Offline scoring uses the retained prompts and responses. Running inference again requires the recorded model assets, dependencies and corpus inputs.
